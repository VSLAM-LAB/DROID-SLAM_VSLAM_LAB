# Training log

Tracks fine-tuning runs for `droidslam-dev` (`train.py`). Background/gotchas live in `CLAUDE.md` (`### Fine-tuning gotchas` and `### Further training improvements`) — this file is just the experiment log: what was run, with what config, what happened, and what's still open. Update it every time a run starts, finishes, or gets evaluated — don't let it drift out of sync with `checkpoints/`.

Commands below are given as pixi task entries (`cmd`/`cwd`) — copy a row's `Command` cell straight into `pixi.toml` under `[feature.droidslam-dev.tasks]` (or run its `cmd` value directly from `Baselines/DROID-SLAM-DEV` in the `droidslam-dev` pixi env).

**Reminder on checkpoint naming:** `train.py` saves every 10000 steps (round numbers, e.g. `_080000.pth`) plus one unconditional save at the true end of the run (odd step count, e.g. `_092568.pth`, `train.py:189-192`). Only the odd-numbered final file has a fully-annealed `OneCycleLR` schedule — always evaluate that one, not the last round-numbered snapshot, unless they happen to coincide.

**Reminder on TensorBoard metric names:** `bad_rot`/`bad_tr` (`geom/losses.py:70-71`) are misnamed — they're `(r_err < 0.1°).mean()` / `(t_err < 1 cm).mean()`, i.e. the fraction of *good* pose edges. Higher is better. `tr_error` is the mean translation norm of the residual relative-pose transform after least-squares scale alignment (`fit_scale`), on 7-frame windows — local pairwise consistency at fitted scale, not metric drift.

**Reminder on what "ATE" means below:** evaluated on ETH sequences the network was trained on (`is_test_scene` is currently dead code for the `vslamlab` dataset — no sequence is genuinely held out, see `CLAUDE.md`). Treat these numbers as "fits the training sequences well," not yet "generalizes to unseen ones."

**Phase 1 findings (2026-08-12 evaluation):**

- **Training set: all ETH sequences, run on the HPC** (the local `VSLAM-LAB-Benchmark/scenes.yaml` listing only `table_3` reflects the local machine, not what trained). So every ETH number above is fit-to-training-data, per the reminder at the top of this file — and, importantly, the tail sequences below failed *despite being in the training set*.
- **Scene-info cache was fresh for all Phase 1 runs**: the HPC's `droid_slam/data_readers/cache/vslamlab.pickle` was deleted before Phase 1 launched (confirmed 2026-08-13), so the co-visibility graphs were built with the post-`8a8fd3c` missing-depth fix and the full ETH scene list — no stale-cache asterisk on these numbers. Reminder for future runs: the cache is keyed only by the name `vslamlab` (`base.py:43`), so delete it again whenever `scenes.yaml`, `depth_read`, or `build_frame_graph` changes.
- **The lr/epochs axis is saturated.** All reasonable settings converge to the same behavior; further sweeping this grid has near-zero expected value.
- **The mean is dominated by a ~5-sequence failure tail** (top-5 sequences carry ~470–570 cm of the ~560–680 cm total summed ATE). The tail decomposes by failure mode, not by hyperparameter:
  - `ceiling_1` (~201 cm): byte-identical across *all* checkpoints including stock `droid.pth` — completely insensitive to training. This is an inference-side failure (degenerate/low-texture scene), not a network-weights problem.
  - `kidnap_1` (~133–147 cm): a relocalization test by construction; DROID-SLAM doesn't relocalize after a kidnap, so this measures a capability the system lacks, not fine-tune quality.
  - Illumination-change sequences (`einstein_flashlight` 120→3–7 cm, `einstein_global_light_changes_1/3`): the one family that *is* training-sensitive, but inconsistently — different configs fix different sequences, which looks like luck-of-the-draw rather than systematic robustness. Photometric augmentation is the targeted lever here.
  - `mannequin_face_1` (~26–39 cm): not improved by any config, slightly worse in some.
- **REPLICA (8 sequences, not in the ETH training data): 0.53 cm baseline → 0.44–0.53 cm fine-tuned.** Fine-tuning on ETH did not damage cross-dataset performance; `lr1e-5` was best there (0.44 cm).
- Median ETH ATE barely moved (0.62 → 0.50–0.56 cm): on the ~50 "easy" sequences the system was already near its floor; all the headroom is in the tail.

## Phase 3 — regularization-off overfit run (from `droid.pth`)

Goal: maximize fit to the ETH training sequences by removing the stochastic/regularizing parts of training, since Phase 1 showed the lr/epochs axis is saturated. Changes vs the Phase 1 center (`eth_lr2e-5_ep8`): photometric augmentation off (`--no_aug_photo`: no color jitter / random grayscale), deterministic fixed-scale resize+center-crop (`--no_aug_crop`), and weight decay off (`--wd 0`). `fmin` stays at the default 8.0 so the run is a clean A/B against Phase 1 — the only delta is regularization; lowering `--fmin` (e.g. to 4, letting low-parallax pairs into training windows, `base.py:128` — widens per-window frame choice but does **not** change the anchor count `M`, which depends only on the graph-size-vs-`n_frames` threshold, `base.py:71`) is a separate single-variable follow-up if this run moves the needle. All changes are sample-time only, so **no `vslamlab.pickle` deletion is needed** (the cached graph is unaffected). Flags added 2026-08-13 (`train.py`, threaded through `dataset_factory` → `RGBDDataset` → `RGBDAugmentor`).

Judge on the `einstein_*` illumination family and the median, not the mean — `ceiling_1`/`kidnap_1`/`mannequin_face_1` are training-insensitive (see Phase 1 findings). Also re-check REPLICA to quantify what pure memorization costs cross-dataset (Phase 1 fine-tunes held it at 0.44–0.53 cm).

## Phase 5 — semi-supervised: Replica gt-anchor + ETH gt-free consistency

Design decision (2026-08-21): treat ETH as having **no usable groundtruth** — supervision comes only from Replica (synthetic gt), while ETH sequences train through a consistency loss (teacher forward on clean images under `no_grad`, student forward on Gaussian-noise-perturbed images, geodesic penalty on relative-pose disagreement; teacher branch stop-gradiented in `losses.py`). Enabled by `--scenes_gt_free` (commit `0d78d0f`): each labeled batch is followed by one gt-free consistency-only step (`fixedp=1`, temporal frame graph, identity pose placeholders), so **`--epochs N` costs 2× the optimizer steps** of an old N-epoch run over the same labeled anchor count. `--con_ramp` linearly warms `w4` from 0. Scene lists live in the benchmark root: `gt.yaml` (labeled: REPLICA office0-4 + room0-1; **room2 held out**, first genuinely-unseen eval scene) and `gt_free.yaml` (gt-free ETH; both yamls must exist on the training machine). Caches are per-yaml, named after the yaml (`--scenes_gt eth.yaml` → `cache/eth.pickle`, `--scenes_gt_free eth.yaml` → `cache/eth_gt_free.pickle` — the two readers store different graphs, so they never share a file; renamed from the interim `vslamlab_gt.<hash>.pickle` scheme on 2026-08-26); the yaml's md5 is stored inside the pickle, so editing a yaml auto-rebuilds instead of loading a stale graph. The old `vslamlab.pickle` is ignored. Labeled TB metrics keep their old names; the gt-free step logs `gt_free/con_loss`, `gt_free/con_rot_error`, `gt_free/con_tr_error`. **Collapse detector:** `gt_free/con_*` at exact 0 while Replica `rot_error` stays healthy = domain-conditional collapse (constant output on ETH-looking images) — kill and lower `--w4`. Before the real queue, run a 3-step full-size smoke on the HPC (`--steps 6`, then delete the `smoke` checkpoint/run) — the gt-free step's teacher pass is `no_grad` so memory ≈ a labeled step, but this hasn't been verified at full `n_frames=7/iters=15` (local 20 GB card can't fit even the labeled step).

**Phase 5 goal statement (user, 2026-08-23):** the objective is improving on the **gt-free (ETH) data**; synthetic/Replica supervision exists only to hold the optimization (anchor against the `w1-0` collapse mode). Replica metrics therefore only need to *not collapse* — they are a sanity check, not a target. Consequences:

- **Noise-consistency is a Jacobian/variance regularizer with a ceiling** (framing agreed 2026-08-23). Penalizing ‖f(x+ε)−f(x)‖ under small Gaussian ε is, to first order, a Tikhonov penalty on the input-Jacobian σ²·E‖J·v‖ (Bishop 1995) — and here f is the *whole windowed estimator* (encoder + correlation + GRU + unrolled DBA), evaluated on ETH images, so it damps how input perturbations propagate through the full solve, conditioning included. What it cannot do: move *bias* — the teacher is the model itself, so nothing pulls predictions toward the truth. Mapped onto the Phase 1/3 failure taxonomy: expect wins on **variance-driven** failures (the `einstein_*` illumination family — 10/70/104 cm run-to-run within one config) and none on bias/degenerate-geometry failures (`ceiling_1`-style). If the pending eval shows "blowups tamed, typical sequences flat," this signal is near-exhausted — more epochs / `w4` tuning won't add much beyond that.
- **Lever hierarchy for actually improving gt-free accuracy** (strongest first; reordered 2026-08-23 to respect the training-philosophy constraint below):
  1. **Stronger in-window teachers** — an *accuracy* (bias-reducing) direction that stays entirely inside the existing windowed `train.py` philosophy; both are single-variable A/Bs vs `replica-eth_semi_w4-05`:
     - **Iteration-asymmetric teacher:** teacher runs more update iterations than the student (e.g. `num_steps=30` vs 15 — teacher is already `no_grad`, so the extra cost is moderate), and every student iterate is pulled toward the teacher's *final* estimate. More unrolled DBA iterations = a strictly better estimator on the same window, so the consistency target sits closer to the truth than the student and the loss gains a bias-reducing component. Implementation: a second `num_steps` arg for the teacher pass + `consistency_loss` comparing all student iterates against the teacher's last (currently it pairs i-th with i-th).
     - **EMA / Mean-Teacher:** teacher weights are an exponential moving average of the student's — the standard semi-supervised upgrade; a temporally-averaged, lower-variance teacher at near-zero implementation risk.
  2. **Directional perturbations** (Jacobian framing of "jitter instead of Gaussian noise"): E‖J·v‖ depends on which directions v are sampled — isotropic Gaussian spreads the penalty budget over pixel-space directions real data never exercises, while photometric jitter / exposure shifts / blur concentrate it along the nuisance directions ETH actually shows (illumination being the documented variance-driven failure family). Same regularizer, aimed where the variance is; not a philosophy change.
  3. **Pseudo-labeling from full SLAM inference** — **user stance (2026-08-23): reluctant; parked** — it changes DROID's training philosophy a fair bit (supervision becomes model-dependent, with confirmation-bias risk on sequences the system gets wrong). Kept on the list because it's the only lever that moves *bias* using outside information: the teacher there is network **+ global backend BA over the full trajectory**, which injects long-range constraints no 7-frame window can see — not pure self-distillation. Mechanics if ever revisited: run full inference on ETH training sequences, keep trajectories as pseudo-groundtruth through the normal supervised path (`groundtruth.csv` format, `synch_gt` applies; third down-weighted scene list optional); filter sequences by the per-sequence eval pattern; depth gap → export `DepthVideo` keyframe disparities or `w3=0` for those scenes. Revisit only if levers 1–2 stall.
  4. **Scalar knobs** (`--epochs 4` ⇒ ~1.4 ETH epochs; `--w4`; ramp) — tune how hard the existing signal is applied, don't change what it can teach.
- **Freedom the current config doesn't use:** since Replica is scaffolding, a larger `--w4`, a >1:1 gt-free:labeled step ratio, or a smaller labeled set are all acceptable if ETH gains demand it. The 1:1 / `w4=0.5` shakedown config is deliberately conservative, not a tuned operating point.
- **Decision rule for `--epochs 4`:** queue it only if this run's ETH ATE shows a win (it then tests whether more ETH coverage compounds it). If ETH is flat/worse, epochs are the wrong knob — go to levers 1–2. Remember each epochs setting is a fresh full run from `droid.pth` (OneCycleLR shape), never a continuation.
